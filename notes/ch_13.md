# Project: GitHub and Jira Integration Using Python

## 1. Project Overview

This project integrates GitHub with Jira Software using Python, Flask, and webhooks.

The goal is to make bug and feature tracking easier for developers, QA engineers, and project managers.

When a developer or QA engineer reports a bug or feature in GitHub, they can use the `/jira` command in the issue's comment section. The system records the request and waits for a manager's approval.

After an authorized manager approves the request, the Python application creates a Jira issue automatically.

### Example Workflow

1. A developer reports a bug in a GitHub repository.
2. The developer comments `/jira` on the issue.
3. GitHub sends a webhook event to the Flask application.
4. The application checks the comment and records the Jira request as pending.
5. A manager reviews the GitHub issue.
6. The manager comments `/jira approve`.
7. The application verifies that the commenter is an authorized manager.
8. Python sends a request to the Jira REST API.
9. Jira creates an issue containing the GitHub issue's title, description, and link.

**Important:** Writing `/jira` only requests a Jira issue. It does not approve the request or immediately create a Jira issue.

---

## 2. What Is Jira Software?

Jira Software is a project management and issue-tracking tool developed by Atlassian. Teams use it to organize and track their work.

Jira can be used to manage:

- Bugs and software defects.
- New features and development tasks.
- Sprint planning and Agile boards.
- Task assignments and priorities.
- Work progress and project status.
- Development workflows.

### Important Jira Terms

| Term | Meaning |
|---|---|
| Project | A place to organize related work |
| Issue | A task, bug, feature, or other work item |
| Issue type | Defines the kind of work, such as Bug or Task |
| Project key | A short identifier for a project, such as `AB` |
| Summary | A short title describing the issue |
| Description | Details about the issue |
| REST API | An interface that lets applications communicate with Jira |
| API token | A credential used to authenticate API requests |

For example, a GitHub issue titled `Login fails with invalid credentials` could become a Bug issue in Jira.

## 5. Understanding GitHub Webhooks

A GitHub webhook automatically sends an HTTP request to an external application when a selected event occurs.

For this project, we will use the **Issue comments** event.

For example, when a developer comments `/jira` on a GitHub issue, GitHub sends a POST request to our Flask application.

The webhook payload contains information such as:

- The comment text.
- The comment author's GitHub username.
- The GitHub issue title.
- The issue number.
- The issue description.
- The issue URL.
- The repository information.

Our Python application reads this information and decides what action to perform.

### Why Do We Need Webhooks?

Without webhooks, a Python script would need to check GitHub repeatedly to find new comments.

With webhooks, GitHub sends an event when a relevant action occurs. This allows our application to react automatically.

## 8. Python Application

Create `app.py` and add the following code.

This starter implementation uses SQLite to store requests. It accepts only the exact `/jira` and `/jira approve` commands, validates GitHub's webhook signature, checks the repository, and requires an authorized manager to approve a pending request.

```python
import os
import hmac
import hashlib
import sqlite3
import logging

import requests
from flask import Flask, request, jsonify
from requests.auth import HTTPBasicAuth

app = Flask(__name__)
logging.basicConfig(level=logging.INFO)

DATABASE = os.environ.get("DATABASE_PATH", "jira_requests.db")

GITHUB_SECRET = os.environ.get("GITHUB_WEBHOOK_SECRET", "")
GITHUB_REPOSITORY = os.environ.get("GITHUB_REPOSITORY", "")

JIRA_BASE_URL = os.environ.get("JIRA_BASE_URL", "").rstrip("/")
JIRA_EMAIL = os.environ.get("JIRA_EMAIL", "")
JIRA_API_TOKEN = os.environ.get("JIRA_API_TOKEN", "")
JIRA_PROJECT_KEY = os.environ.get("JIRA_PROJECT_KEY", "")
JIRA_ISSUE_TYPE = os.environ.get("JIRA_ISSUE_TYPE", "Task")

MANAGER_USERS = {
    username.strip().lower()
    for username in os.environ.get(
        "MANAGER_GITHUB_USERS", ""
    ).split(",")
    if username.strip()
}


def get_db():
    connection = sqlite3.connect(DATABASE)
    connection.row_factory = sqlite3.Row
    return connection


def initialize_database():
    with get_db() as db:
        db.execute("""
            CREATE TABLE IF NOT EXISTS jira_requests (
                repository TEXT NOT NULL,
                issue_number INTEGER NOT NULL,
                issue_title TEXT NOT NULL,
                issue_body TEXT,
                issue_url TEXT NOT NULL,
                requested_by TEXT NOT NULL,
                status TEXT NOT NULL DEFAULT 'pending',
                jira_key TEXT,
                PRIMARY KEY (repository, issue_number)
            )
        """)


initialize_database()


def verify_github_signature(raw_body, signature):
    """Verify that the webhook was signed with our secret."""
    if not GITHUB_SECRET or not signature:
        return False

    digest = hmac.new(
        GITHUB_SECRET.encode("utf-8"),
        raw_body,
        hashlib.sha256
    ).hexdigest()

    expected = f"sha256={digest}"

    return hmac.compare_digest(expected, signature)


def create_jira_issue(issue_title, issue_body, issue_url):
    """Create a Jira issue using the Jira REST API."""
    url = f"{JIRA_BASE_URL}/rest/api/3/issue"

    description_text = (
        f"Reported from GitHub: {issue_url}\n\n"
        f"{issue_body or 'No description provided.'}"
    )

    # Jira Cloud uses Atlassian Document Format for descriptions.
    payload = {
        "fields": {
            "project": {
                "key": JIRA_PROJECT_KEY
            },
            "issuetype": {
                "name": JIRA_ISSUE_TYPE
            },
            "summary": issue_title,
            "description": {
                "type": "doc",
                "version": 1,
                "content": [
                    {
                        "type": "paragraph",
                        "content": [
                            {
                                "type": "text",
                                "text": description_text
                            }
                        ]
                    }
                ]
            }
        }
    }

    response = requests.post(
        url,
        json=payload,
        headers={
            "Accept": "application/json",
            "Content-Type": "application/json"
        },
        auth=HTTPBasicAuth(JIRA_EMAIL, JIRA_API_TOKEN),
        timeout=15
    )

    response.raise_for_status()

    return response.json()["key"]


@app.route("/health", methods=["GET"])
def health():
    return jsonify({"status": "running"}), 200


@app.route("/github-webhook", methods=["POST"])
def github_webhook():
    raw_body = request.get_data()

    signature = request.headers.get(
        "X-Hub-Signature-256", ""
    )

    if not verify_github_signature(raw_body, signature):
        return jsonify({"error": "Invalid webhook signature"}), 401

    event = request.headers.get("X-GitHub-Event", "")

    # Ignore unrelated GitHub events.
    if event != "issue_comment":
        return jsonify({"message": "Event ignored"}), 200

    payload = request.get_json(silent=True) or {}

    # Process only newly created comments.
    if payload.get("action") != "created":
        return jsonify({"message": "Action ignored"}), 200

    repository = payload.get("repository", {}).get("full_name", "")

    # Accept events only from the configured repository.
    if repository.lower() != GITHUB_REPOSITORY.lower():
        return jsonify({"message": "Repository ignored"}), 200

    issue = payload.get("issue", {})
    comment = payload.get("comment", {})

    # This example supports issues, not pull requests.
    if "pull_request" in issue:
        return jsonify({"message": "Pull request ignored"}), 200

    issue_number = issue.get("number")
    comment_body = comment.get("body", "").strip()
    commenter = comment.get("user", {}).get("login", "").lower()

    if not issue_number or not commenter:
        return jsonify({"error": "Missing issue or commenter"}), 400

    # Command 1: request a Jira issue.
    if comment_body == "/jira":
        with get_db() as db:
            existing = db.execute(
                """
                SELECT status
                FROM jira_requests
                WHERE repository = ? AND issue_number = ?
                """,
                (repository, issue_number)
            ).fetchone()

            if existing:
                return jsonify({
                    "message": "A Jira request already exists",
                    "status": existing["status"]
                }), 200

            db.execute(
                """
                INSERT INTO jira_requests (
                    repository,
                    issue_number,
                    issue_title,
                    issue_body,
                    issue_url,
                    requested_by,
                    status
                )
                VALUES (?, ?, ?, ?, ?, ?, 'pending')
                """,
                (
                    repository,
                    issue_number,
                    issue.get("title", "Untitled issue"),
                    issue.get("body") or "",
                    issue.get("html_url", ""),
                    commenter
                )
            )

        app.logger.info(
            "Jira request recorded for %s#%s by %s",
            repository, issue_number, commenter
        )

        return jsonify({
            "message": "Jira request saved. Waiting for manager approval."
        }), 200

    # Command 2: manager approves the pending request.
    elif comment_body == "/jira approve":
        if commenter not in MANAGER_USERS:
            return jsonify({
                "error": "Only authorized managers can approve requests"
            }), 403

        with get_db() as db:
            pending = db.execute(
                """
                SELECT *
                FROM jira_requests
                WHERE repository = ?
                  AND issue_number = ?
                  AND status = 'pending'
                """,
                (repository, issue_number)
            ).fetchone()

        if not pending:
            return jsonify({
                "message": "No pending Jira request exists"
            }), 200

        try:
            jira_key = create_jira_issue(
                pending["issue_title"],
                pending["issue_body"],
                pending["issue_url"]
            )

            with get_db() as db:
                db.execute(
                    """
                    UPDATE jira_requests
                    SET status = 'created', jira_key = ?
                    WHERE repository = ?
                      AND issue_number = ?
                      AND status = 'pending'
                    """,
                    (jira_key, repository, issue_number)
                )

            app.logger.info(
                "Created Jira issue %s for %s#%s",
                jira_key, repository, issue_number
            )

            return jsonify({
                "message": "Jira issue created",
                "jira_key": jira_key
            }), 200

        except (requests.RequestException, KeyError, ValueError):
            app.logger.exception("Failed to create Jira issue")

            # Leave the request pending so it can be investigated
            # and retried after the underlying problem is fixed.
            return jsonify({
                "error": "Could not create Jira issue. Check application logs."
            }), 502

    # Ignore comments that do not match our commands.
    else:
        return jsonify({"message": "Comment is not a Jira command"}), 200


if __name__ == "__main__":
    app.run(host="127.0.0.1", port=5000, debug=False)
```

### How the Code Works

**1. Webhook verification**

The application validates `X-Hub-Signature-256` using the configured webhook secret. Invalid requests are rejected.

**2. Event filtering**

Only newly created `issue_comment` events from the configured repository are processed. Other events are ignored.

**3. Exact command matching**

The code checks the entire trimmed comment:

```python
if comment_body == "/jira":
```

This means comments such as `/jira please` or `I need /jira` do not match.

The approval command is checked separately:

```python
elif comment_body == "/jira approve":
```

**4. Manager authorization**

The manager's GitHub username must appear in `MANAGER_GITHUB_USERS`. Other users receive a `403 Forbidden` response.

**5. Pending request storage**

SQLite records the GitHub issue and its status. A request must exist before it can be approved.

**6. Jira issue creation**

After approval, the application sends a POST request to the Jira REST API. It uses the GitHub issue title as the Jira summary and includes the description and GitHub URL.

**7. Duplicate protection**

The database's primary key prevents the same GitHub repository and issue number from being registered as multiple pending requests through this workflow.

This is useful for avoiding duplicate requests, but a production implementation should also handle concurrent approvals, API timeouts, and uncertain outcomes using stronger locking and idempotency controls.

## 9. Configure Jira Software

### Step 1: Create a Jira project

1. Sign in to your Atlassian account.
2. Open Jira.
3. Create a project.
4. Choose a suitable project type.
5. Record the project key, such as `AB`.

Use the same key in `JIRA_PROJECT_KEY`.

### Step 2: Create an API token

Create a Jira API token from your Atlassian account's security settings.

Configure:

- `JIRA_BASE_URL`: Your Jira Cloud site URL.
- `JIRA_EMAIL`: The email associated with the Jira account.
- `JIRA_API_TOKEN`: The API token.
- `JIRA_PROJECT_KEY`: Your project key.
- `JIRA_ISSUE_TYPE`: An issue type available in the project, such as `Bug` or `Task`.

The Jira account must have permission to create issues in the selected project.

**Important:** The issue type must exist in the Jira project, and the account must have the required permissions. Otherwise, Jira may reject the request.

### Step 3: Understand the API request

The application sends a request to:

```text
POST https://your-domain.atlassian.net/rest/api/3/issue
```

Jira receives the JSON payload and creates an issue if the credentials, project, issue type, and fields are valid.

The response contains the new Jira issue key, for example `AB-123`.

## 10. Configure the GitHub Webhook

You need a publicly reachable HTTPS endpoint for GitHub to send webhook events to. A local address such as `127.0.0.1:5000` cannot be reached directly by GitHub.

### Step 1: Deploy or expose the application

For production, deploy Flask behind a production WSGI server and HTTPS reverse proxy, such as Gunicorn and Nginx.

Your endpoint might look like:

```text
https://your-domain.com/github-webhook
```

For local experimentation, a secure tunneling service can temporarily expose a local application, but do not use a temporary development URL as a production endpoint.

### Step 2: Open repository settings

1. Open your GitHub repository.
2. Go to **Settings**.
3. Select **Webhooks**.
4. Click **Add webhook**.

### Step 3: Configure the webhook

Set these values:

| Setting | Value |
|---|---|
| Payload URL | `https://your-domain.com/github-webhook` |
| Content type | `application/json` |
| Secret | The same secret as `GITHUB_WEBHOOK_SECRET` |
| SSL verification | Enabled |
| Events | Select individual events |
| Event | Issue comments |

Save the webhook.

GitHub will send the selected event payloads to your application.

### Step 4: Verify the webhook

Open the webhook's delivery history in GitHub.

Check that:

- The payload URL is correct.
- The delivery succeeds.
- The Flask logs show the incoming request.
- Invalid signatures are rejected.
- Ordinary comments are ignored.
- `/jira` creates a pending request.
- Only an authorized manager's `/jira approve` can create a Jira issue.

A successful webhook delivery only means your endpoint returned a successful HTTP response. You must also verify the application's logs and the resulting Jira issue.

## 12. Security and Production Improvements

Before using this integration in a real team, consider the following improvements:

- **Use HTTPS:** Protect communication between GitHub and your application.
- **Verify webhook signatures:** Reject requests with invalid signatures.
- **Restrict the repository:** Accept events only from the intended GitHub repository.
- **Restrict approvals:** Use an explicit allowlist of authorized manager accounts.
- **Protect credentials:** Store Jira tokens and webhook secrets in a secret manager.
- **Use persistent storage:** SQLite is suitable for a simple demonstration. For a production service, consider managed PostgreSQL or another durable database.
- **Prevent duplicate issues:** Handle simultaneous approvals and retries. A database status alone does not fully protect against every API timeout or race condition.
- **Add timeouts and logging:** Record errors without logging secrets.
- **Limit permissions:** Give the Jira account only the permissions it needs.
- **Monitor failures:** Send alerts when webhook processing or Jira requests fail.
- **Run Flask properly:** Use Gunicorn or another production WSGI server instead of the development server.
- **Avoid unsafe retries:** If Jira creates an issue but the response is lost, a retry could create a duplicate. Use an idempotency strategy or reconciliation process.

### A note about approvals

This example authorizes managers by their GitHub usernames. That is a simple starting point, but it is not a complete enterprise approval system. For stronger controls, use a managed identity and authorization process, maintain an audit trail, and ensure the approval policy is enforced consistently.

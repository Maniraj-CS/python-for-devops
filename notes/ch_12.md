# Python for DevOps: Flask

## 1. What Is Flask?

Flask is a lightweight Python web framework used to build web applications and APIs.

A web framework provides tools that help us handle HTTP requests, return responses, and organize application code.

### Why Do We Use Flask?

- Build REST APIs using Python.
- Create simple web applications.
- Build internal tools for DevOps teams.
- Create health-check endpoints for applications.
- Develop services that communicate with other applications.
- Build webhook endpoints for automation workflows.

### Example

A DevOps team might create a Flask API that returns the status of an application.

```python
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "DevOps application is running!"

if __name__ == "__main__":
    app.run(debug=True)
```

When someone visits the root URL, the application returns a message.

## 2. Installing Flask

Create a project directory:

```bash
mkdir flask-devops
cd flask-devops
```

Create a virtual environment:

```bash
python3 -m venv venv
```

Activate it on Linux:

```bash
source venv/bin/activate
```

Install Flask:

```bash
pip install flask
```

Save dependencies:

```bash
pip freeze > requirements.txt
```

The `requirements.txt` file records the installed Python packages and their versions.

To install the recorded dependencies later:

```bash
pip install -r requirements.txt
```

## 3. Creating Your First Flask Application

Create a file named `app.py`.

```python
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Hello from Flask!"

if __name__ == "__main__":
    app.run(debug=True)
```

Run the application:

```bash
python app.py
```

Open this URL in your browser:

```text
http://127.0.0.1:5000
```

You should see:

```text
Hello from Flask!
```

### Understanding the Code

**`from flask import Flask`**

Imports the Flask class from the Flask package.

**`app = Flask(__name__)`**

Creates the Flask application object.

**`@app.route("/")`**

Connects the root URL `/` to the function below it.

**`def home():`**

Defines the function that handles requests to this route.

**`return "Hello from Flask!"`**

Returns a response to the client.

**`if __name__ == "__main__":`**

Runs the development server when the file is executed directly.

**`debug=True`**

Enables debugging features. Use it only during local development, never in production.

## 4. Understanding Routes

A route connects a URL path to a Python function.

```python
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Home Page"

@app.route("/about")
def about():
    return "About Page"

@app.route("/health")
def health():
    return "Application is healthy"

if __name__ == "__main__":
    app.run(debug=True)
```

Examples:

| URL path | Response |
|---|---|
| `/` | Home Page |
| `/about` | About Page |
| `/health` | Application is healthy |

### Dynamic Routes

Dynamic routes accept values from the URL.

```python
@app.route("/user/<username>")
def user_profile(username):
    return f"Hello, {username}!"
```

For example, visiting `/user/maniraj` returns:

```text
Hello, maniraj!
```

You can also specify a data type.

```python
@app.route("/server/<int:server_id>")
def server_info(server_id):
    return f"Server ID: {server_id}"
```

Here, Flask converts `server_id` to an integer.

## 5. HTTP Methods

HTTP methods describe the type of operation a client wants to perform.

| Method | Common purpose |
|---|---|
| GET | Retrieve information |
| POST | Create or submit information |
| PUT | Replace an existing resource |
| PATCH | Update part of a resource |
| DELETE | Delete a resource |

### Example: GET and POST

```python
from flask import Flask, request

app = Flask(__name__)

@app.route("/status", methods=["GET"])
def get_status():
    return {"status": "running"}

@app.route("/deployments", methods=["POST"])
def create_deployment():
    data = request.get_json()

    return {
        "message": "Deployment request received",
        "data": data
    }, 201

if __name__ == "__main__":
    app.run(debug=True)
```

The GET endpoint returns application status.

The POST endpoint accepts JSON data and returns HTTP status code `201`, which means a resource was created. In this example, it only acknowledges the request; it does not perform a real deployment.

## 6. Reading Request Data

Flask provides the `request` object to access incoming request information.

### A. Query Parameters

Query parameters appear after `?` in a URL.

```python
from flask import request

@app.route("/search")
def search():
    name = request.args.get("name", "unknown")
    return {"name": name}
```

Example URL:

```text
/search?name=server1
```

Response:

```json
{
  "name": "server1"
}
```

### B. JSON Request Body

Clients commonly send JSON when calling APIs.

```python
from flask import request

@app.route("/server", methods=["POST"])
def create_server():
    data = request.get_json()

    if not data or "name" not in data:
        return {"error": "Server name is required"}, 400

    return {"server_name": data["name"]}, 201
```

The API expects a JSON request body such as:

```json
{
  "name": "web-server"
}
```

The `400` status code means the request is invalid or missing required information.

---

## 7. Returning JSON Responses

JSON is a common format for exchanging data between applications.

Flask automatically converts returned dictionaries into JSON responses.

```python
@app.route("/api/info")
def api_info():
    return {
        "application": "DevOps API",
        "version": "1.0",
        "status": "running"
    }
```

Example response:

```json
{
  "application": "DevOps API",
  "version": "1.0",
  "status": "running"
}
```

JSON is useful when one application needs to communicate with another application.

For example, a monitoring system could call an API to check whether a service is running.

## 8. HTTP Status Codes

Status codes tell the client what happened to its request.

| Code | Meaning |
|---|---|
| 200 | Request successful |
| 201 | Resource created |
| 400 | Bad request |
| 401 | Authentication required or failed |
| 403 | Request forbidden |
| 404 | Resource not found |
| 500 | Internal server error |
| 503 | Service temporarily unavailable |

Example:

```python
@app.route("/not-found")
def not_found():
    return {"error": "Resource not found"}, 404
```

Returning the correct status code helps clients and monitoring tools understand the result.

---

## 9. Error Handling

An API should handle errors and return useful responses instead of exposing internal details.

```python
@app.route("/divide/<int:number>")
def divide(number):
    if number == 0:
        return {"error": "Number cannot be zero"}, 400

    return {"result": 100 / number}
```

In this example, zero is rejected before division.

For larger applications, you can create reusable error handlers.

```python
@app.errorhandler(404)
def handle_not_found(error):
    return {"error": "Route not found"}, 404
```

Do not return passwords, access tokens, or sensitive internal error details to clients.

## 10. Environment Variables

Environment variables allow an application to read configuration without hardcoding it in the source code.

For example, create an environment variable on Linux:

```bash
export APP_ENV=development
```

Read it in Flask:

```python
import os
from flask import Flask

app = Flask(__name__)

APP_ENV = os.environ.get("APP_ENV", "production")

@app.route("/environment")
def environment():
    return {"environment": APP_ENV}
```

The application reads `APP_ENV`. If it is missing, the value defaults to `production`.

In real projects, keep secrets in a suitable secret manager rather than committing them to Git.

## 11. Logging in Flask

Logging helps developers and DevOps teams understand what an application is doing.

```python
from flask import Flask

app = Flask(__name__)

@app.route("/health")
def health():
    app.logger.info("Health endpoint was requested")
    return {"status": "healthy"}

if __name__ == "__main__":
    app.run()
```

The application writes a log message when the endpoint is called.

Logs can help investigate:

- Application errors.
- Failed requests.
- Unexpected behavior.
- Service availability issues.

In production, configure logging so that messages can be collected by your infrastructure's logging system.

## 12. Connecting Flask with Other Python Code

Flask can call regular Python functions. This is useful for keeping application logic separate from HTTP routes.

```python
from flask import Flask

app = Flask(__name__)

def get_service_status():
    return {
        "nginx": "running",
        "api": "running"
    }

@app.route("/services")
def services():
    return get_service_status()

if __name__ == "__main__":
    app.run()
```

The `get_service_status()` function contains the application logic. The Flask route calls that function and returns its result.

In a real DevOps tool, the function could retrieve service information, read a configuration file, or query a monitoring system.

---

## 13. Testing a Flask API

You can test Flask routes without starting a real network server by using Flask's test client.

```python
from flask import Flask

app = Flask(__name__)

@app.route("/health")
def health():
    return {"status": "healthy"}

def test_health():
    client = app.test_client()

    response = client.get("/health")

    assert response.status_code == 200
    assert response.get_json() == {"status": "healthy"}
```

Save the code in `test_app.py` and install pytest:

```bash
pip install pytest
```

Run the test:

```bash
pytest -v
```

Tests help confirm that an API returns the expected response and status code.

# Project 1: Build a DevOps Health-Check API

## 14. Project Overview

**Goal:** Build a Flask API that reports whether the application is responding.

### Folder structure

```text
flask-health-api/
├── app.py
├── requirements.txt
└── README.md
```

### `app.py`

```python
from flask import Flask
from datetime import datetime, timezone
import os

app = Flask(__name__)

APP_NAME = os.environ.get("APP_NAME", "devops-health-api")

@app.route("/")
def home():
    return {
        "application": APP_NAME,
        "message": "API is running"
    }

@app.route("/health")
def health():
    return {
        "status": "healthy",
        "timestamp": datetime.now(timezone.utc).isoformat()
    }

@app.route("/ready")
def ready():
    return {
        "status": "ready"
    }

if __name__ == "__main__":
    app.run(debug=True)
```

### `requirements.txt`

```text
Flask
```

### Run the project

```bash
pip install -r requirements.txt
python app.py
```

Test the endpoints:

```bash
curl http://127.0.0.1:5000/
curl http://127.0.0.1:5000/health
curl http://127.0.0.1:5000/ready
```

### DevOps concepts covered

- HTTP endpoints.
- Health checks.
- JSON responses.
- Environment variables.
- Application monitoring basics.

**Important:** These endpoints show that the Flask process is responding. A real readiness check should also verify critical dependencies, such as a database, when the application needs them.

# Project 2: Deploy Flask Using Docker, Nginx, and GitHub Actions

## 15. Project Overview

Build a small Flask API and deploy it using a DevOps workflow.

### Architecture

```text
Developer
   |
   v
GitHub Repository
   |
   v
GitHub Actions
   |
   v
Build and Test Docker Image
   |
   v
Deploy to Linux Server
   |
   v
Nginx Reverse Proxy
   |
   v
Flask Application
```

### Technologies

- Python and Flask: Build the API.
- Docker: Package the application.
- Nginx: Handle incoming HTTP requests and forward them to Flask.
- GitHub Actions: Automate testing and deployment.
- Linux: Host the application.
- Terraform: Optionally create the cloud infrastructure.
- Ansible: Optionally configure the server.

### Features to implement

1. Create `/health` and `/api/info` endpoints.
2. Add input validation and error handling.
3. Write tests using pytest.
4. Create a Dockerfile.
5. Configure Nginx as a reverse proxy.
6. Build a GitHub Actions workflow to run tests.
7. Add a controlled deployment step to a Linux server.
8. Add logs and basic monitoring.

For production, run Flask through a production WSGI server such as Gunicorn rather than Flask's built-in development server. Keep debug mode disabled.

---

## 16. Flask Best Practices

- Keep debug mode disabled in production.
- Use a production WSGI server.
- Validate incoming request data.
- Return meaningful HTTP status codes.
- Store configuration in environment variables.
- Never hardcode secrets in source code.
- Write tests for important routes.
- Use logging to investigate failures.
- Use Nginx or another suitable reverse proxy when needed.
- Run the application with the minimum permissions it requires.
- Keep dependencies updated.
- Avoid putting long-running operations directly inside HTTP requests without a suitable background-job design.

# Python for DevOps: Boto3

## 1. What is Boto3?

**Boto3 is the AWS SDK for Python.** It allows us to use Python code to work with AWS services.

With Boto3, we can automate AWS tasks instead of performing every task manually in the AWS Console.

### Why do we use Boto3?

- Create and manage EC2 instances.
- Upload and download files from S3.
- Create and delete EBS snapshots.
- Get information about AWS resources.
- Monitor AWS resources.
- Automate repetitive tasks using Python.
- Build automation scripts for AWS Lambda.

### Example

Suppose you want to list all EC2 instances in your AWS account.

You can open the AWS Console and check them manually, or use Python with Boto3 to retrieve the information automatically.

```python
import boto3

ec2 = boto3.client("ec2")

response = ec2.describe_instances()

for reservation in response["Reservations"]:
    for instance in reservation["Instances"]:
        print(instance["InstanceId"], instance["State"]["Name"])
```

This script retrieves EC2 instance information and prints each instance ID and its current state.


- Default output format

**Security note:** Never hardcode AWS access keys in your Python scripts or upload them to GitHub.

For AWS Lambda, use an IAM execution role instead of manually configuring access keys.

## 3. Understanding Boto3: Client and Resource

Boto3 provides two common ways to interact with AWS services: `client` and `resource`.

### A. Client

A client provides a low-level interface to AWS APIs. It uses AWS operation names and returns responses as Python dictionaries.

```python
import boto3

ec2 = boto3.client("ec2")

response = ec2.describe_instances()

print(response)
```

Here, `describe_instances()` calls the EC2 API to retrieve instance information.

### B. Resource

A resource provides a higher-level, object-oriented interface. It is available for some AWS services, including EC2 and S3.

```python
import boto3

ec2 = boto3.resource("ec2")

for instance in ec2.instances.all():
    print(instance.id, instance.state["Name"])
```

### Client vs Resource

| Client | Resource |
|---|---|
| Low-level API interface | Higher-level object interface |
| Uses API operation names | Uses Python objects and methods |
| Supports a broad range of AWS API operations | Available for selected services |
| Useful for detailed API control | Useful for object-oriented workflows |

**DevOps tip:** Learn the client interface first. It is useful for many automation tasks and works well with AWS Lambda.

## 4. Understanding Boto3 Sessions

A session stores configuration used when connecting to AWS, such as the region and credentials provider.

```python
import boto3

session = boto3.Session(region_name="ap-southeast-2")

ec2 = session.client("ec2")

response = ec2.describe_instances()
print(response)
```

This example uses the `ap-southeast-2` region.

Always select the region where your resources exist. Otherwise, you might not see the resources you expect.

## 5. Common Boto3 Operations

### A. List EC2 Instances

```python
import boto3

ec2 = boto3.client("ec2")

response = ec2.describe_instances()

for reservation in response["Reservations"]:
    for instance in reservation["Instances"]:
        print({
            "id": instance["InstanceId"],
            "state": instance["State"]["Name"],
            "type": instance["InstanceType"]
        })
```

### B. List S3 Buckets

```python
import boto3

s3 = boto3.client("s3")

response = s3.list_buckets()

for bucket in response["Buckets"]:
    print(bucket["Name"])
```

### C. Create an EBS Snapshot

An EBS snapshot is a point-in-time backup of an EBS volume.

```python
import boto3

ec2 = boto3.client("ec2")

response = ec2.create_snapshot(
    VolumeId="vol-0123456789abcdef0",
    Description="Manual backup"
)

print("Snapshot ID:", response["SnapshotId"])
```

Replace the example volume ID with a real EBS volume ID in your account.

### D. Add Tags to a Snapshot

Tags help us identify and manage AWS resources.

```python
import boto3

ec2 = boto3.client("ec2")

ec2.create_tags(
    Resources=["snap-0123456789abcdef0"],
    Tags=[
        {"Key": "Project", "Value": "BackupAutomation"},
        {"Key": "CleanupEligible", "Value": "true"},
        {"Key": "SourceInstanceId", "Value": "i-0123456789abcdef0"}
    ]
)
```

The `SourceInstanceId` tag records which instance the snapshot belongs to. This relationship is not automatically guaranteed for every snapshot; our backup workflow must add the tag when creating it.

### E. Delete an EBS Snapshot

```python
import boto3

ec2 = boto3.client("ec2")

ec2.delete_snapshot(
    SnapshotId="snap-0123456789abcdef0"
)

print("Snapshot deletion requested")
```

**Important:** Deleting a snapshot is a destructive operation. AWS permissions, retention policies, and backup requirements must be checked before deletion.

---

## 6. Handling Errors in Boto3

AWS operations can fail because of missing permissions, invalid resource IDs, or temporary service errors.

Use `ClientError` to handle AWS API errors.

```python
import boto3
from botocore.exceptions import ClientError

ec2 = boto3.client("ec2")

try:
    response = ec2.describe_instances()
    print(response)

except ClientError as error:
    print("AWS API error:", error)
```

For a production script, log the error and decide whether to retry or stop. Do not silently ignore errors.

# Project: AWS Snapshot Cleanup Automation

## 7. Project Overview

**Project name:** Automated EBS Snapshot Cleanup Using AWS Lambda and Boto3

### The problem

Suppose you create an EC2 instance and take an EBS snapshot to back up its data.

Later, you delete the EC2 instance. The snapshot can still remain in your AWS account because deleting an instance does not automatically delete every snapshot created from its volumes.

These unused snapshots can continue to incur storage costs.

### Our solution

We will create a Python script using Boto3 and run it through AWS Lambda.

The Lambda function will:

1. Find snapshots explicitly marked as eligible for cleanup.
2. Check the source EC2 instance recorded in the snapshot's tags.
3. Confirm that the source instance no longer exists.
4. Check that the snapshot is older than the configured retention period.
5. Skip snapshots referenced by existing AMIs owned by our account.
6. Log eligible snapshots and, when enabled, request their deletion.

We will use a **30-day retention period** in this example. You can change it to match your backup policy.

### Architecture

```text
EC2 Instance
     |
     v
EBS Volume
     |
     v
Create EBS Snapshot
     |
     v
Add cleanup tags
     |
     v
EC2 Instance is deleted
     |
     v
Amazon EventBridge schedule
     |
     v
AWS Lambda (Python + Boto3)
     |
     v
Check tags, age, source instance
and AMI references
     |
     v
Delete eligible snapshots
```

The scheduled Lambda function checks resources periodically. It does not need to run at the exact moment the instance is deleted.

| Tag | Example value | Purpose |
|---|---|---|
| `Project` | `BackupAutomation` | Identifies the project |
| `CleanupEligible` | `true` | Explicitly allows cleanup consideration |
| `SourceInstanceId` | `i-0123456789abcdef0` | Identifies the source instance |

The cleanup function will ignore snapshots without these tags.

**Important:** Use this cleanup policy only for snapshots managed by your project. Do not assume every old snapshot is unused.

## 9. Lambda Function Code

Create a file named `lambda_function.py`.

This version starts in **dry-run mode**. It reports which snapshots qualify without deleting them. After you verify the logs and backup policy, you can explicitly enable deletion.

```python
import os
import logging
from datetime import datetime, timezone, timedelta

import boto3
from botocore.exceptions import ClientError

logger = logging.getLogger()
logger.setLevel(logging.INFO)

ec2 = boto3.client("ec2")

RETENTION_DAYS = int(os.environ.get("RETENTION_DAYS", "30"))
DRY_RUN = os.environ.get("DRY_RUN", "true").lower() == "true"


def get_existing_instance_ids():
    """Return IDs of EC2 instances that still exist."""
    instance_ids = set()
    paginator = ec2.get_paginator("describe_instances")

    for page in paginator.paginate():
        for reservation in page["Reservations"]:
            for instance in reservation["Instances"]:
                instance_ids.add(instance["InstanceId"])

    return instance_ids


def get_ami_snapshot_ids():
    """Return snapshot IDs referenced by AMIs owned by this account."""
    snapshot_ids = set()
    paginator = ec2.get_paginator("describe_images")

    for page in paginator.paginate(Owners=["self"]):
        for image in page["Images"]:
            for mapping in image.get("BlockDeviceMappings", []):
                ebs = mapping.get("Ebs", {})
                snapshot_id = ebs.get("SnapshotId")

                if snapshot_id:
                    snapshot_ids.add(snapshot_id)

    return snapshot_ids


def get_tag_value(tags, key):
    """Return the value of a tag, or None if the tag is missing."""
    for tag in tags:
        if tag["Key"] == key:
            return tag["Value"]

    return None


def lambda_handler(event, context):
    now = datetime.now(timezone.utc)
    cutoff = now - timedelta(days=RETENTION_DAYS)

    instance_ids = get_existing_instance_ids()
    ami_snapshot_ids = get_ami_snapshot_ids()

    paginator = ec2.get_paginator("describe_snapshots")

    deleted = 0
    skipped = 0
    examined = 0

    for page in paginator.paginate(
        OwnerIds=["self"],
        Filters=[
            {
                "Name": "tag:Project",
                "Values": ["BackupAutomation"]
            },
            {
                "Name": "tag:CleanupEligible",
                "Values": ["true"]
            }
        ]
    ):
        for snapshot in page["Snapshots"]:
            examined += 1

            snapshot_id = snapshot["SnapshotId"]
            source_instance_id = get_tag_value(
                snapshot.get("Tags", []),
                "SourceInstanceId"
            )

            # Require a recorded source instance.
            if not source_instance_id:
                logger.info("Skipping %s: missing source instance tag", snapshot_id)
                skipped += 1
                continue

            # Keep snapshots that are still within the retention period.
            if snapshot["StartTime"] > cutoff:
                logger.info("Skipping %s: within retention period", snapshot_id)
                skipped += 1
                continue

            # Keep snapshots whose source instance still exists.
            if source_instance_id in instance_ids:
                logger.info("Skipping %s: source instance still exists", snapshot_id)
                skipped += 1
                continue

            # Avoid deleting snapshots referenced by owned AMIs.
            if snapshot_id in ami_snapshot_ids:
                logger.info("Skipping %s: referenced by an owned AMI", snapshot_id)
                skipped += 1
                continue

            # Do not delete anything while dry-run is enabled.
            if DRY_RUN:
                logger.info(
                    "DRY RUN: %s qualifies for cleanup",
                    snapshot_id
                )
                continue

            try:
                ec2.delete_snapshot(SnapshotId=snapshot_id)
                logger.info("Deletion requested for %s", snapshot_id)
                deleted += 1

            except ClientError:
                logger.exception(
                    "Failed to delete snapshot %s",
                    snapshot_id
                )
                raise

    logger.info(
        "Cleanup complete. Examined=%s, Skipped=%s, DeletionRequests=%s, DryRun=%s",
        examined,
        skipped,
        deleted,
        DRY_RUN
    )

    return {
        "statusCode": 200,
        "body": {
            "examined": examined,
            "skipped": skipped,
            "deletion_requests": deleted,
            "dry_run": DRY_RUN
        }
    }
```

### How the script works

- `os.environ.get()` reads Lambda environment variables.
- `datetime.now(timezone.utc)` gets the current UTC time.
- `timedelta(days=RETENTION_DAYS)` calculates the retention cutoff.
- `get_paginator()` processes results across multiple API pages.
- `describe_instances()` retrieves existing EC2 instances.
- `describe_images()` finds snapshots referenced by AMIs owned by your account.
- `describe_snapshots()` retrieves your account's snapshots matching the required tags.
- `delete_snapshot()` requests deletion of an eligible snapshot.
- `logger.info()` and `logger.exception()` write messages to CloudWatch Logs.

### Important limitation

This is a conservative starter project, not a complete backup-governance system. It checks for existing instances and references from owned AMIs, but it does not prove that a snapshot is unnecessary. For example, an independent recovery plan or a dependency outside this account may still require it. Keep required backups protected by policy, test with dry-run logs, and review your recovery requirements before enabling deletion.

## 10. Configure AWS Lambda

### Step 1: Create a Lambda function

1. Open the AWS Lambda Console.
2. Choose **Create function**.
3. Select **Author from scratch**.
4. Enter `ebs-snapshot-cleanup`.
5. Choose Python 3.x.
6. Select or create an execution role.
7. Create the function.

### Step 2: Add the code

Paste the code into `lambda_function.py` in the Lambda code editor.

The code uses `boto3`, which is included in the standard AWS Lambda Python runtime. If developing locally, install Boto3 with pip.

### Step 3: Configure environment variables

In **Configuration → Environment variables**, add:

| Key | Value |
|---|---|
| `RETENTION_DAYS` | `30` |
| `DRY_RUN` | `true` |

Keep dry-run mode enabled while testing.

### Step 4: Configure an EventBridge schedule

Create a schedule in Amazon EventBridge, such as running the function once per day.

Set the target to your `ebs-snapshot-cleanup` Lambda function.

This allows the cleanup check to run automatically without someone opening the AWS Console.

## 11. IAM Permissions

The Lambda execution role needs permission to read the required EC2 resources and, only when deletion is enabled, delete snapshots.

Example policy for this project:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ec2:DescribeInstances",
        "ec2:DescribeImages",
        "ec2:DescribeSnapshots"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "ec2:DeleteSnapshot"
      ],
      "Resource": "*"
    }
  ]
}
```

Attach the policy to the Lambda execution role. For production, refine the permissions and resource restrictions where supported, and separate read-only testing permissions from deletion permissions.

The Lambda role also needs CloudWatch Logs permissions. You can attach the AWS-managed `AWSLambdaBasicExecutionRole` policy for standard logging.

**Never give a Lambda function broad permissions that it does not need.** Test its behavior before allowing deletion.

## 13. Cost Optimization: Important Considerations

Snapshot cleanup can reduce storage costs, but deleting every snapshot whose source instance is missing is unsafe.

Before enabling deletion:

- Keep snapshots required by recovery policies.
- Use a defined retention period.
- Apply explicit cleanup tags.
- Check whether snapshots are referenced by AMIs.
- Keep dry-run mode on until you have reviewed real results.
- Monitor Lambda execution and failures through CloudWatch.
- Consider AWS Backup lifecycle policies for centrally managed backups.
- Remember that snapshot storage charges depend on stored snapshot data and AWS pricing rules.

For an additional safety improvement, you can require a separate approval tag, such as `CleanupApproved=true`, before deletion.

## Quick Summary

- **Boto3:** Python SDK for AWS automation.
- **Client:** Low-level interface to AWS API operations.
- **Resource:** Higher-level, object-oriented interface for supported services.
- **IAM role:** Provides AWS permissions to Lambda without hardcoded access keys.
- **Lambda:** Runs the Python cleanup code.
- **EventBridge:** Runs the cleanup function on a schedule.
- **CloudWatch Logs:** Helps inspect execution and errors.
- **Dry-run mode:** Lets you review proposed cleanup before deleting resources.

**Main lesson:** Production-style DevOps automation is not only about deleting unused resources. It is about identifying eligible resources, protecting required backups, logging every action, and reducing cost without risking data loss.
